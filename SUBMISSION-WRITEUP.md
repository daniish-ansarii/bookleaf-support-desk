# BookLeaf Support Desk — Approach

I prioritized a complete support workflow for both sides: authors can sign in, view their books, submit queries, and follow replies; operations staff can triage the shared queue, update status and priority, assign work, leave private notes, and respond. Authentication and role checks are enforced in the API so an author cannot retrieve another author's books or tickets.

The service uses a small Node.js REST API and a browser-native frontend to keep setup simple. Local development uses a JSON file; the hosted app uses Neon Postgres so state survives Vercel's stateless functions. For this assignment, the database stores application state as one JSONB document. That reduces setup and migration work, but it limits concurrent writes and reporting; I would replace it with normalized tables and migrations before scaling.

AI is optional and runs server-side with Gemini Flash Lite, selected for a lightweight classification and drafting workload. New tickets first receive local category and priority estimates, so AI outages do not block ticket submission. Model output is constrained to allowed values and treated as a suggestion admins can override. Draft prompts use the ticket's recent messages and a bounded Knowledge Base excerpt, treat ticket text as untrusted input, and instruct the model to ask for missing facts instead of inventing policy. Drafts require human review before sending. The provided requirements referenced a BookLeaf Knowledge Base, but did not include its policy content; the app documents this gap and currently avoids unsupported policy claims.

To keep the deployment straightforward on Vercel, updates use five-second polling rather than persistent sockets. Attachments are represented in the UI but are not uploaded. Demo users share sample passwords because credentials were absent from the supplied dataset; that is for evaluation only.

Given more time, I would add per-user invitations and password recovery, rate limiting and audit logs, a normalized schema with migrations and indexes, secure object storage with file scanning, push updates, and monitoring. I would also add an approved knowledge base and an evaluation set for classification quality, response accuracy, latency, and fallback behavior. The repository and live demo should only expose company-provided author data with explicit company approval; otherwise, I would publish sanitized fixtures and use approved evaluation accounts.
